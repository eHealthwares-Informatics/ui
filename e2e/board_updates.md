### PROPOSED TICKET (Mac agent: file if agreed — evidence below)

**Title:** [rxsoft/ui] Wizard matrix tabs: row-level validation errors are never rendered (invalid price/quantity saves blocked silently)

**Body:** In the items create wizard, the Price List and Stock Entries matrix tabs validate rows on the per-row Save action (`field-group-add.tsx` `saveRow` → `validatePricingRow` / `validateStockRow`, e.g. "Unit price must be a positive number", "Quantity cannot be negative"). On an invalid row the save is correctly blocked and `row.error` is written into row state — but **nothing renders it**: (a) `saveRow` returns before any notification (`field-group-add.tsx:126-135`); (b) no matrix column defines the `error` render fn that `table/utils.tsx:117-121` supports (`column.error?.(row)`); (c) the Mantine input error slot stays empty because `row.error` is never wired into the field's `error` prop. Net effect: a user entering a negative price/quantity and clicking the row's Save gets **zero feedback** — violates the repo's own alpha-QA rule 2 ("visible validation before submission", `frontend/e2e/tasks/schema_validation_task.md`). Repro evidence: run 4c12b, TC-WIZARD-02 traces (`test-results/tests-rxsoft-items-wizard--927c4-validation-on-invalid-price-admin{,-retry1}/`) — page advanced/row stayed 'Unsaved' with no visible error. Suggested fix: wire `row.error` into the injected column `error` renderer in `field-group-add.tsx`'s `matrixColumns` (one-line: `error: (row) => row.error`) + optionally a red notification on failed row save.

**Refactor recommendations for dev (evidence from runs 4c12/4c12b, non-blocking, queued for the next ui PR):**

1. **Delete the no-op `updateField` stub in the price matrix column** (`products/types/schema.tsx` ~268: `updateField: (row, name, value) => {}, //updateMatrixRow(...)`). It never runs — `field-group-add.tsx`'s `matrixColumns` useMemo overrides every editable column's `updateField` — but it reads like the write-path and mislead two QA sessions today. Make the contract explicit: the matrix component owns row updates; the schema should not define per-column `updateField` at all.
2. **Handle the async-save rejection in `tab-groups.tsx` `handleNext`** — `await stepSubmit(activeStep)` has try/finally but no catch; a failed save (e.g. HTTP 500) propagates as an unhandled promise rejection out of the onClick (visible as a console error; WIZARD-06 currently relies on it). One catch that keeps the wizard on the current step makes the error path explicit.
3. **Consolidate row action mechanisms** — `ActionCell` renders both saveRow/resetRow icon buttons AND a `rowActions` dropdown; the schema's `rowActions: [{label:'Save', action:'save-price'}]` strings appear unconsumed (`action: 'save-price'` matches nothing in the render path). Pick one mechanism, delete the dead config.
4. **Per-run org state path (e2e infra)** — `e2e/.runtime/org-state.json` is a singleton shared by every configured run; with concurrent runs on this box (shop specs + items wizard) one run's teardown deprovisions the other's org. Include a run-scoped suffix (env var or `--project`) in `ORG_STATE_PATH`, or serialize runs by design.
5. **`data-testid` on row-action ActionIcons + rendered field errors** — the row Save/Reset buttons are icon-only (no accessible name — violates both the a11y intent and `data_test_id_task.md`; e2e must fall back to `svg.lucide-save` class matching), and rendered validation errors have no testid (the e2e had to match an empty `[role="alert"]` placeholder). Adding `data-testid="row-save"`/`"row-reset"`/`"field-error"` unblocks testid-first selectors.
6. **Minor perf** — `field-group-add.tsx`'s `matrixColumns` useMemo depends on `rows` (rebuilds every column — and re-renders every editable cell — on each keystroke). Use functional `setRows`/`updateField` with a stable callback and drop `rows` from deps.
